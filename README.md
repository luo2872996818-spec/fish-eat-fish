# 大鱼吃小鱼 · fish-eat-fish

手机网页小游戏：吃比自己小的鱼长大，躲开比自己大的鱼，撞上就掉命。

**纯前端、零依赖、零构建 —— 手机点开链接就能玩。**

| 项目 | 内容 |
|---|---|
| 线上地址 | **https://luo2872996818-spec.github.io/fish-eat-fish/** |
| 当前阶段 | **阶段 0：部署自检页**（验证「手机能打开 + 触摸位置准确 + 帧率正常」） |
| 技术栈 | 原生 HTML + CSS + JavaScript（ES Module），Canvas 2D 渲染 |
| 依赖 | 无。不用 npm，不装任何第三方库 |
| 目标平台 | 手机浏览器优先；电脑浏览器用鼠标也能玩（Pointer Events 一套代码同时支持） |

## 怎么运行

### 线上（手机上玩）
手机浏览器打开：**https://luo2872996818-spec.github.io/fish-eat-fish/**

### 本地（电脑上改代码时预览）
代码用了 `<script type="module">`，**不能直接双击 `index.html`**
（`file://` 协议下模块会被浏览器的 CORS 策略拦住）。必须起一个本地服务器：

```powershell
cd E:\AIProject\fish-eat-fish
python tools\serve.py
```

然后浏览器打开 http://localhost:8000
（脚本启动时会**直接把手机该访问的局域网地址打印出来**，不用自己查 ipconfig）

> ⚠️ **不要用 `python -m http.server`**：这台电脑的 Windows 注册表把 `.js` 登记成了
> `text/plain`，而浏览器对 `type="module"` 会强制检查 MIME 类型，
> 结果就是脚本被拒绝执行、页面一片空白。
> `tools/serve.py` 就是为绕开这个坑写的，详见 [docs/notes.md](docs/notes.md)。

详细步骤见 [docs/deployment.md](docs/deployment.md)。

## 目录结构

```
fish-eat-fish/
├── index.html              ← 门牌号：只做跳转，把访问者送到 ./v1/
├── .gitignore              ← 告诉 Git 哪些文件不用上传
├── tools/
│   └── serve.py            ← 本地开发服务器（专治 Windows 上 .js 被当成纯文本的坑）
├── docs/                   ← 文档
│   ├── deployment.md       ← 部署上线操作手册（照着做就能上线）
│   ├── requirements.md     ← 需求文档（做什么、不做什么）
│   ├── design.md           ← 设计文档（架构、模块划分、数据流）
│   └── notes.md            ← 开发笔记（踩过的坑、决策记录）
├── v1/                     ← 第一版的全部内容
│   ├── index.html          ← 页面骨架（手机端的 meta 配置都在这）
│   ├── style.css           ← 手机端适配（每个坑写的都有注释）
│   ├── assets/             ← 美术素材（v1 为空，画面全部用 Canvas 代码画）
│   └── src/
│       ├── main/           ← 入口、游戏循环、数值配置
│       ├── scenes/         ← 场景：菜单 / 游戏中 / 结束
│       ├── entities/       ← 实体：玩家鱼 / 敌方鱼
│       ├── systems/        ← 系统：生成 / 碰撞 / 渲染 / 难度
│       ├── platform/       ← 平台适配层（尺寸、输入、设备）★ 关键
│       └── utils/          ← 通用工具（数学函数等）
└── tests/                  ← 测试代码
```

**为什么游戏放在 `v1/` 而不是根目录？**
因为你说了「后续可能会升级」。以后做 v2 时，只要把根目录 `index.html` 里的
跳转目标从 `./v1/` 改成 `./v2/`，**已经分享出去的链接不会失效**，
而且老版本还在 `v1/` 里能访问 —— v2 万一出问题，改回来一秒搞定。

## 架构约定（改代码前请先读这一节）

### 1. 分层规则

```
main / scenes / entities / systems   ← 游戏逻辑：只管玩法，"怎么显示、怎么输入"都不管
              ↓ 只通过这层的方法交互
platform/ (viewport / input / device) ← 平台适配：屏幕尺寸、触摸/鼠标/键盘、设备能力
```

**最重要的一条纪律：游戏逻辑层绝不直接调用 `addEventListener`，
也绝不直接读 `event` 对象。** 一切输入都通过 `platform/input.js` 暴露的
`input.target` 来获取。

好处：将来要加键盘操作、改成横屏、上微信小程序，**只改 `platform/` 一个文件夹**，
上层代码一行都不用动。

### 2. 输入只用 Pointer Events

用 `pointerdown / pointermove / pointerup`，不用 `touchstart` 那一套。
因为浏览器把手指、鼠标、触控笔统一成了 pointer 事件 ——
一套代码三种设备通用，不需要写 `if (是手机)` 的分支。

### 3. 所有可调数值集中在 `src/main/config.js`

鱼的速度、大小、判定比例、难度曲线……全部放一个文件。
调手感的时候不用翻十个文件。（该文件在阶段 1 建立）

### 4. 文件名一律小写

GitHub Pages 跑在 Linux 上，**区分大小写**。
本地 Windows 不区分，所以 `Style.css` 和 `style.css` 在本地都能跑，
上传后线上就会 404。所有文件名统一小写，从源头避开这个坑。

### 5. 帧率安全

游戏循环用固定步长（累加器 + 固定 1/60 秒步进），
手机上偶尔掉帧时不会出现「鱼瞬移穿过大鱼」的穿透 bug。（阶段 1 实现）
